# Error Policy

PortfoTrack separates user errors from programmer or invariant violations.
This boundary is part of the architecture.

## User Errors

Use the custom application error hierarchy for invalid user-controlled input.

Examples:

- Missing required request fields.
- Invalid request parameter values.
- Wrong user-provided value type.
- Domain-level validation failure caused by user input.

These errors should be suitable for conversion into clear web/API responses.

## Programmer or Invariant Errors

Use native Python exceptions for impossible states, broken internal contracts,
or bugs in trusted code paths.

Examples:

- A trusted DTO generated by save logic is missing a required key.
- A supposedly internal mapping has an impossible shape.
- Code calls a function with a type that violates its contract.

Do not wrap these errors in application error classes merely to make them
look user-facing.

## Assertions

Assertions are not allowed in production code.
They are allowed in tests.
